# Check Point API Framework: Instructions for Coding Agents

This repository is an extensible base for applications that use the Check Point Management API. Build application-specific functionality on top of the framework; do not replace the framework's connection, session, context, throttling, or task-handling layers without an explicit request.

## Required Reading Order

Before changing code, read these files in order:

1. `README.md`
2. `docs/architecture.md`
3. `docs/adding-workflows.md`
4. `src/check-point-client.js`
5. `src/session-manager.js`
6. `src/server.js`
7. `test/framework.test.js`

Also read `docs/gaia-run-script-presets.md` before adding or changing Gaia commands or run-script presets.

For UI work, read `DESIGN.md`, `docs/design-patterns.md`, and `skills/framework-design/SKILL.md`. These describe the approved workbench and extension patterns. Retain native HTML/CSS/JavaScript unless the user requests a migration.

## Framework Contracts: Do Not Break

- Preserve all management types: SMS, Smart-1 Cloud, and MDS.
- Preserve Smart-1 Cloud URL normalization, including the tenant context path and `/web_api` endpoint.
- Preserve MDS session contexts: `primary`, `mds`, `global`, and `system-data`. A context can be unavailable; do not assume every context exists.
- Keep credentials and Check Point SIDs server-side. Never put passwords, API keys, or SIDs in browser storage, URLs, logs, source files, or returned API payloads.
- Use `SessionManager` for Management API calls. Do not call `CheckPointClient` directly from a workflow or the browser.
- Use `sessions.command()` for a normal Management API command and `sessions.list()` for paginated collection commands.
- Use `sessions.runScript()` for Gaia execution. Never issue `run-script` and treat its immediate task object as final output.
- Maintain large-environment throttling for both Management API and Gaia calls.
- Preserve confirmation UI for state-changing Management API commands and non-monitoring Gaia presets.
- Preserve the raw Check Point task response as a collapsed troubleshooting view when changing result rendering.

## Where New Code Belongs

- Put application-specific collection, evaluation, reporting, or remediation logic in `src/workflows/`.
- Add an explicit route in `src/server.js` only when a workflow needs its own endpoint.
- Keep reusable connection, session, pagination, task polling, and result normalization in the existing core modules.
- Keep reusable Gaia command definitions in `public/data/gateway-run-script-presets.json` and follow the Gaia guide.
- Treat `public/` as the presentation layer. It must call local `/api/*` routes, not Check Point directly.

## Change Requirements

- Make the smallest change that fulfills the requested behavior.
- Do not remove existing management types, contexts, throttles, or safeguards to simplify an app-specific workflow.
- For any new state-changing action, add a warning/confirmation and document its expected impact.
- Add or update tests in `test/framework.test.js` for core behavior changes. At minimum, run `npm run check` before handing work back.
- Keep generated API catalog files generated by `npm run catalog:update`; do not hand-edit them.

## Definition of Done

Before declaring a change complete:

1. Run `npm run check` successfully.
2. Confirm the login path still supports SMS, Smart-1 Cloud, and MDS contexts when affected.
3. Confirm run-script output remains decoded, target-associated, and clean for success, error, and no-output responses when affected.
4. State any new configuration, privileges, or operational risks in the README or relevant guide.

## Required Login Default

Allow Self-Signed Certificate must default to checked for SMS, Smart-1 Cloud, and MDS. Preserve this default in derived apps and agent-driven changes. An omitted API login ignoreTls field defaults to true; an explicit false (unchecked) enables certificate verification for all session contexts. This setting disables TLS certificate verification, not encryption, and does not authenticate the server certificate. Users must remain able to uncheck it. Do not disable TLS verification globally or for catalog downloads.
